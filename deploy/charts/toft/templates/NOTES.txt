{{- if .Values.blockAwsMetadata }}

BLOCK_AWS_METADATA
  Shared mode blocks the metadata endpoints with an iptables rule and refuses to
  start if it cannot. Isolated mode writes a NetworkPolicy egress rule, and
  NOTHING VERIFIES IT IS ENFORCED: a cluster whose CNI has no policy engine
  accepts the object and ignores it, with no error anywhere.

  The engine is chosen when the cluster is created and this chart cannot add it.
  On AKS that is `--network-policy azure` (or `cilium`) at `az aks create`, which
  cannot be set afterwards; on EKS the default VPC CNI does not enforce egress
  policy at all. Without one, deployed apps in isolated mode can reach
  169.254.169.254 and take the identity of the node they run on.
{{- end }}

APP OUTPUT
  A shared app's output is copied onto the platform pod's stdout as kind=app
  records. An isolated app's output is its own pod's stdout, and nothing keeps
  it but your cluster's log agent: without one it exists only while kubelet
  holds the current and previous container, and every redeploy and restart
  replaces the pod. Pods carry toft.dev/app-id and toft.dev/app-slug labels.
